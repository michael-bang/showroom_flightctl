[#fleetupdates]
=== Fleet Update policies

The updates part of the Fleet configuration provides you with functionality to *Use basic configuration* which will roll out any change
to the Fleet as soon as the edge manager agent does its next update. This is great if you want to roll out updates as soon as possible, but might
not be what you want to do in production.
If you unselect the *Use basic configuration* you can do more advanced configurations for your roll out. With the advanced configuration you can: *set roll out policies,
set disruption budget and set update policies*

The *set rollout policies* make it possible to select the order of the roll out meaning that you can have some device being updated first and only if
that goes well continue to the rest. 

image::m2-create-fleet-set-rollout-policies.png[link=self, window=blank, width=100%]

The *set disruption budget* ensure that you will not update all devices at once and if problems occur having a minimum set of available running devices

image::m2-create-fleet-set-disruption-budget.png[link=self, window=blank, width=100%]

The *set update policies* make it possible to define a schedule for when the updates should be applied.

image::m2-create-fleet-set-update-policies.png[link=self, window=blank, width=100%]

We will stick to the *basic configuration* in this lab.

=== Observability

NOTE: In addition to Events and Alerts, Edge Manager supports Observability capabilities for device and service *metrics, profiling, tracing, and audit logs*. This data can be stored over time to enable historical analysis and long-term insights.

Configuring Observability is beyond the scope of our lab; however, at a high level the following describes this functionality and flow: +

* Uses OpenTelemetry Collector on a device and forwards collected data to the Telemetry Gateway +
* Telemetry Gateway saves collected data from devices and service, or forwards data to external Collector +
* Standalone observability stack is available for Edge Manager on RHEL and/or the Observability stack in OpenShift can be utilized
